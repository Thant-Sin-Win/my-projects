# Technical Implementation Details

## Microsoft Sentinel SOAR Honeypot Lab

------------------------------------------------------------------------

### Environment Configuration

The lab environment was implemented within Microsoft Azure using the
following components:

  -----------------------------------------------------------------------
  Resource                       Description
  ------------------------------ ----------------------------------------
  Azure Virtual Machine          Internet-facing Windows Server acting as
                                 honeypot

  Network Security Group         Controls inbound RDP access (TCP 3389)

  Log Analytics Workspace        Centralised log collection

  Microsoft Sentinel             SIEM platform

  Automation Rule                Playbook trigger

  Azure Logic App                SOAR response playbook
  -----------------------------------------------------------------------

RDP (TCP 3389) was intentionally exposed to the public internet to
simulate real-world brute-force activity.

------------------------------------------------------------------------

### Log Collection

Windows Security Logs were forwarded to the Log Analytics Workspace
using the Azure Monitoring Agent.

Relevant events collected:

  Event ID   Description
  ---------- ----------------------
  4625       Failed Login Attempt
  4624       Successful Login

------------------------------------------------------------------------

### Analytic Rule Configuration

A scheduled analytics rule was created in Microsoft Sentinel to detect
repeated failed authentication attempts.

Query logic:

    SecurityEvent
    | where EventID == 4625
    | summarize FailedAttempts = count()
        by IpAddress, Account, bin(TimeGenerated, 5m)
    | where FailedAttempts >= 5

Alert grouping was enabled to generate incidents upon detection of
suspicious behaviour.

------------------------------------------------------------------------

### Automation Rule

An automation rule was created to trigger a playbook when an incident is
generated by the above analytic rule.

**Trigger:**\
When incident is created

**Condition:**\
Analytic rule name contains "Brute Force Attack Detected"

**Action:**\
Run Playbook → Auto-Block-BruteForce-Attacker-IP

------------------------------------------------------------------------

### Playbook Design

The Logic App playbook was created using an incident-triggered workflow.

Workflow structure:

Microsoft Sentinel Incident Trigger\
↓\
Delay (1 minute)\
↓\
For Each (Incident.relatedEntities)\
↓\
Condition: entity.kind == "Ip"\
↓\
HTTP Action → Azure NSG REST API

------------------------------------------------------------------------

### Entity Extraction

Initial implementation using:

Entities - Get IPs

returned an empty array due to playbook execution prior to entity
enrichment.

This was resolved by:

-   Adding a delay after the incident trigger\
-   Iterating through the relatedEntities field directly

ForEach input:

    triggerBody()?['object']?['properties']?['relatedEntities']

Condition inside loop:

    @equals(item()?['kind'], 'Ip')

IP address value used in HTTP body:

    @{item()?['properties']?['address']}

------------------------------------------------------------------------

### HTTP Action (NSG Rule Creation)

Azure Management REST API was used to dynamically create inbound deny
rules.

**Method:**\
PUT

**URI format:**

    https://management.azure.com/subscriptions/<subscription-id>
    /resourceGroups/<resource-group>
    /providers/Microsoft.Network
    /networkSecurityGroups/<nsg-name>
    /securityRules/BlockBruteForceIP-@{replace(item()?['properties']?['address'],'.','-')}
    ?api-version=2022-05-01

**Headers:**\
Content-Type: application/json

**Authentication:**\
Managed Identity\
Audience: https://management.azure.com

**Body:**

    {
      "properties": {
        "priority": "@{add(3000, int(last(split(item()?['properties']?['address'], '.'))))}",
        "direction": "Inbound",
        "access": "Deny",
        "protocol": "Tcp",
        "sourcePortRange": "*",
        "destinationPortRange": "3389",
        "sourceAddressPrefix": "@{item()?['properties']?['address']}",
        "destinationAddressPrefix": "*"
      }
    }

------------------------------------------------------------------------

### Managed Identity Configuration

System Assigned Managed Identity was enabled for the Logic App.

**Role Assignment:**\
Network Contributor

**Scope:**\
Network Security Group resource

This permission is required for the playbook to update NSG security
rules via Azure Resource Manager.

### Current Limitations

Correlation-based detection of:

Successful login after multiple failures

requires multi-event logic and has not yet been automated within the
playbook workflow.

Future development will include:

-   Detection using EventID 4624 following repeated 4625 events\
-   Additional automation conditions\
-   Workbook-based geo-visualisation of attacker IPs
